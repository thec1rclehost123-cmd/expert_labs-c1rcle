## 2. Payments: merged where (corrected 2026-10-24)
Earlier versions of this package listed the payments correctness stack as unmerged and said refunds "never settle". **Both were wrong for staging.** The payments and finance code on the reviewed backend checkout is **identical to `origin/staging`**. #115, #117, #118, #124, #126, #130 and #133 were closed but their commits landed through the merged clean branch **#135** (10-18); **#136** (financial engine: journal v2, refund executor, disputes, chargebacks, reconciliation, transition) and **#125** (payout gate) are merged. Still open: #127 part 2 (tax rules), #129, #119, #121, #116, #131. Frontend PR #72 is closed with its work on staging. Full table and the open legal, tax and finance decisions: `../10-payments-and-finance/09-status-prs-and-open-decisions.md`.
**October 2026 payment audit:** every finding (tickets sellable for any event status, promo codes not validated, refund-held seat resold, cross-buyer idempotency, late-payment refund indistinguishable, last-seat overselling, sub-₹1 totals, late payment taking a new buyer's seat, per-user cap bypass, hold latency) is **fixed on staging** (via #135). Open from the audit: hard-coded 18% GST on guest fees (needs the CA and the tax-rule store), the 10-minute hold length (a business choice).
**New payments defects (verified):** the legacy partner ledger never advances `pending` entries so partner available balance is 0; the journal cutover has no route or script; a second payment against a converted hold is captured with no order and no refund; `payment.failed` is ignored; no scheduled repair or reconciliation; the webhook has no rate limit and adapter calls have no timeout.

## 5. Operational risks
- Free-tier Render: sleeps when idle (30–40 s cold start), single instance; the repo's own `render.yaml` warns to upgrade before real payments.
- Health check path was unset on the live service as of 2026-10-18 (unverified).
- Rotating `NGINX_ORIGIN_VERIFY_SECRET` currently causes an outage until nginx accepts two secrets (not built).
- Frontend CI smoke tests hit `*.vercel.app` URLs, not real hostnames; a frontend onboarding test is flaky under CI load.
- `.mcp.json` files are tracked and contain a developer's local paths; seed scripts embed a development password and assume the real `c1rcle-v2` project.

## 6. Blocked on people, not code
